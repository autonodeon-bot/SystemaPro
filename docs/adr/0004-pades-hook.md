# ADR 0004. PDF верификация: QR-штамп сейчас, PAdES-T потом

- **Status:** Accepted
- **Date:** 2026-04-19

## Контекст

Заключение о ТД / ЭПБ уходит заказчику и в Ростехнадзор. Нужен способ
отличить оригинал от подделки: проверка должна быть однострочной
(заказчик → скан QR → "да, подлинный"). В идеале — PAdES-T (ETSI EN 319 142),
но КриптоПро CSP на сервере ещё не развёрнут.

## Решение (двухэтапное)

### Сейчас (v3.30)
1. При подписании отчёта:
   - sha256(pdf) → `content_sha256`
   - генерируется `verification_token` (64 chars)
   - запись в `report_signatures`
2. На последней странице PDF — QR-штамп со ссылкой:
   `https://neftcontrol.ru/api/verify/report/{token}`
3. Публичный endpoint:
   - `GET /api/verify/report/{token}` → `{valid, signer, signed_at, sha256}`
   - `POST /api/verify/report/{token}/check-hash` (multipart PDF) →
     сравнение sha256 для доказательства целостности.
4. Отзыв заключения: `revoked_at`, `revoke_reason`.

Это не квалифицированная подпись в терминах 63-ФЗ, но:
- Позволяет однозначно идентифицировать оригинал;
- Даёт механизм отзыва;
- Доступно без криптопровайдера.

### Потом (v3.31+)
- Включить `PADES_ENABLED=1`;
- Установить `pyhanko` (уже есть hook);
- Настроить `PADES_CERT_PATH` + TSA URL;
- `signature_type` в реестре становится `pades-t`, `signature_blob` — CMS.

Код уже готов к переключению: `pdf_stamping.sign_pdf_pades()` — единая точка.

## Альтернативы

- **Прямо сейчас КриптоПро**: требует покупки лицензий, настройки CSP,
  обучения подписантов. Не блокируем релиз.
- **Блокчейн/Timestamping anchor**: overengineering для прикладной системы
  технической диагностики.
