## 1. Цель работ

Закрыть замечания к оформлению технического отчёта ТО (форма to-1) по аннотированному PDF `report (5).pdf` и обеспечить полный путь данных: **задание (web) → обследование (mobile) → генерация Word/PDF**.

---

## 2. Исходные замечания (анализ PDF)

Проанализирован файл с аннотациями (41 заметка). Ключевые проблемы:

1. Титул и разделы 1–15 не заполнялись (данные были только в приложениях).
2. Местонахождение оборудования попадало в графу заказчика.
3. Для отсутствующих документов стояли «—» / «отсутствует» вместо «Не предоставлено».
4. Ломалась читаемость размеров и марки стали (09Г2С) в узких колонках.
5. Дублировался номер «Таблица № 6».
6. Не хватало полей в web (договор, сроки) и mobile (формулировки, опасность среды и т.д.).

**Корневая причина пустого основного отчёта:** официальный шаблон `to-1.docx` помещает основной текст (титул, оглавление, разд. 1–15) внутрь Word **content control (SDT)**. Библиотека `python-docx` через `doc.tables` / `doc.paragraphs` видела в основном приложения, поэтому filler не заполнял тело отчёта.

Материалы анализа: `backend/scripts/_pdf_annots.json`, `_extract_pdf_annots.py`.

## 3. Исправления генерации отчёта (to-1) — версии 3.7.8 / 3.7.9

| Проблема | Решение |
|---|---|
| Пустой титул и разд. 1–15 | Заполнение SDT: титул, заказчик, исполнитель, специалисты, приборы, объекты, теххарактеристика, работы, документы, предыдущие ТО, результаты, выводы |
| СОДЕРЖАНИЕ не с новой страницы | Разрыв страницы перед оглавлением |
| Задвоение «Таблица № 6» | У раздела 10 → **Таблица № 7** |
| Местонахождение в шапке приложений | Иерархия заказчика режется: последний сегмент → место нахождения |
| Статус документов | **«Не предоставлено»** при отсутствии |
| «09Г2С», даты | `noWrap` в узких ячейках |
| Лаборатория / аттестат | Из настроек организации |
| ВИК: шероховатость / освещённость | Значения по умолчанию в таблице приборов |

Файл: `backend/form_template_filler.py`  
Smoke-тест: `backend/scripts/_smoke_to1_remarks.py`.

## 4. Веб: выдача задания — версия 3.7.9

В форме создания/редактирования задания добавлены:

- форма ТО (`report_form_id`);
- № и дата договора;
- период работ (с / по);
- основание;
- № технологической карты.

Данные хранятся в таблице `assignments` (автомиграция колонок при старте API) и:

- отдаются в mobile API;
- подмешиваются в `inspection.data` при генерации отчёта, если в обследовании пусто.

Файлы: `CreateAssignmentModal.tsx`, `EditAssignmentModal.tsx`, `assignments_api.py`, `models.py`, `reports_crud_api.py`, `main.py`.

## 5. Мобильное приложение — версии 3.7.7 … 3.7.9

### 3.7.7 (UX и нормативы)
- схема контроля на карте обследования;
- блокировка подписания без таблички / схемы / УЗТ / заключения;
- предупреждение при синхронизации неполных данных;
- светлая тема: читаемые заголовки на панелях;
- нормативные документы: загрузка/скачивание PDF/DOC/DOCX;
- просмотр состава разделов шаблона отчёта;
- русские подписи типов обследований и статусов.

### 3.7.8–3.7.9 (данные для отчёта)
- поля класса опасности, взрыво-/пожароопасности, условного обозначения, схемы подключения, климатического исполнения, массы, циклов, срока службы;
- расчётная толщина и данные о сварке по элементам корпуса;
- объём контроля и организация-исполнитель в предыдущих обследованиях;
- выпадающие формулировки разд. 14–15 и анализа документации;
- блок оперативной (функциональной) диагностики с оценками;
- автоподтягивание договора / сроков / техкарты из задания.

Файлы (основные): `vessel_inspection_screen.dart`, `inspection_*_section.dart`, `report_formulation_options.dart`, модели `assignment.dart` / `vessel_checklist.dart`.

## 7. Как проверить

1. Создать задание: заполнить договор, период, техкарту, форму to-1.
2. Установить APK **3.7.9+46**.
3. Выполнить обследование: теххарактеристика, оперативная диагностика, документы, схема/УЗТ.
4. Синхронизировать и сгенерировать Word/PDF.
5. Проверить титул, разд. 1–2, 9–15 и шапки приложений («Не предоставлено», местонахождение, таблица № 7).

## 8. Что остаётся на следующие итерации

Не входит в обязательный минимум текущего релиза:

1. Библиотека схем контроля с редактированием размеров/швов **или** загрузка файла схемы/техкарты на этапе задания (сейчас схема — в mobile, № техкарты — на задании).
2. Полноценный реестр приборов ВИК (образцы шероховатости, люксметр) как отдельные карточки в Instrument Registry.
3. Заполнение остальных форм ТО (кроме to-1 / to-13 / to-25) тем же качеством.
4. Версионирование сгенерированных отчётов в БД.
5. Поля договора на уровне проекта/клиента с автоподстановкой во все задания.
