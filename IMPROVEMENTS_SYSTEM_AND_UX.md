# Предложения по улучшению системы и мобильного приложения

## Офлайн и онлайн: что должно быть заполнено для стабильной работы

- **Онлайн:** при первом входе загружаются задания, оборудование, инженеры, ОПО, поверенное оборудование и сохраняются локально. При последующем офлайн-входе эти данные используются.
- **Офлайн:** сохраняются черновики и подписанные обследования в `pending_inspections`; все вложения — в папке `offline_documents`. После появления сети нужно выполнить синхронизацию (экран заданий / меню).
- **Рекомендация:** перед выездом в поле один раз открыть список заданий при включённом интернете, чтобы кэш заданий и оборудования был заполнен.

## 20 улучшений для работы всей системы (бэкенд + веб + отчёты)

1. **Единый источник правды для отчётов** — вынести формирование структуры отчёта (разделы, порядок) в конфиг (JSON/YAML) или БД, чтобы менять макет без правок кода.
2. **Версионирование шаблонов отчётов** — хранить версию шаблона и при генерации подставлять корректный макет в зависимости от типа оборудования и даты.
3. **Очередь генерации отчётов** — тяжёлые отчёты (полный DOCX с картинками) формировать в фоне (Celery/RQ или воркер FastAPI), отдавать ссылку на скачивание по готовности.
4. **Проверка целостности вложений** — перед генерацией отчёта проверять наличие всех файлов по `document_files` и писать в лог/уведомление список отсутствующих.
5. **Лимиты и квоты** — ограничение размера загружаемых файлов, лимит числа вложений на одно обследование, квота на хранение по организации/пользователю.
6. **Единый формат ошибок API** — все ответы с ошибками в формате `{ "detail": "...", "code": "...", "errors": [] }` для удобной обработки на мобильном и вебе.
7. **Аудит изменений** — логирование кто и когда создал/изменил обследование, отчёт, задание; отдельная таблица или поле `updated_by`/`created_by`.
8. **Резервное копирование и восстановление** — автоматические бэкапы БД и каталога `uploads`, скрипты восстановления и проверки.
9. **Метрики и мониторинг** — счётчики запросов, время генерации отчётов, ошибки синхронизации; интеграция с Prometheus/Grafana или аналогом.
10. **Валидация данных при приёме** — жёсткая проверка типов и обязательных полей при создании/обновлении обследований и опросников; понятные сообщения об ошибках.
11. **Кэширование справочников** — кэш списков ОПО, инженеров, типов оборудования с TTL и инвалидацией при изменении.
12. **Пакетная выгрузка отчётов** — API/задача «сформировать отчёты по списку обследований» (ZIP с DOCX/PDF) для массовой печати.
13. **Поддержка подписей в отчёте** — поле «подпись» (изображение или факт подписания в приложении) и вставка в конец отчёта.
14. **Водяной знак на черновиках** — при генерации отчёта из черновика добавлять пометку «ЧЕРНОВИК» на каждой странице.
15. **Экспорт в PDF из DOCX** — опция конвертации сгенерированного DOCX в PDF на сервере (например, LibreOffice headless или python-docx + docx2pdf) для единообразия.
16. **Синхронизация по таймеру** — на мобильном периодическая попытка синхронизации в фоне (WorkManager) с уведомлением при успехе/ошибке.
17. **Повторная отправка только неудачных файлов** — при синхронизации сохранять, какие именно файлы не загрузились, и при следующей синхронизации отправлять только их.
18. **Восстановление после сбоя отчёта** — при падении генерации отчёта не оставлять «битый» файл; писать во временный путь и перемещать только после успешного завершения.
19. **Роли и права на отчёты** — разграничение: кто может генерировать полный отчёт, кто — только краткий; привязка к ролям в БД.
20. **Документация API (OpenAPI)** — актуальная схема всех эндпоинтов с примерами запросов/ответов и кодами ошибок для интеграции и отладки.

## 20 улучшений юзабилити мобильного приложения

1. **Индикатор офлайн/онлайн** — в шапке или в меню всегда видно: «Офлайн» / «Сеть есть», иконка и цвет (серый/зелёный).
2. **Счётчик несинхронизированных обследований** — на экране заданий или в меню: «Ожидают отправки: 3», с переходом к списку при нажатии.
3. **Подтягивание вниз (pull-to-refresh)** — на экранах списков заданий, оборудования, ОПО обновление списка жестом и индикатором загрузки.
4. **Подсказка при первом офлайн-входе** — если нет кэша заданий/оборудования: «Для работы офлайн сначала войдите при подключённом интернете и откройте список заданий».
5. **Подтверждение перед выходом при несохранённых данных** — при нажатии «Назад» в форме обследования, если есть несохранённые изменения: «Сохранить черновик? Да / Нет / Отмена».
6. **Крупные зоны нажатия** — кнопки «Сохранить», «Подписать», «Синхронизировать» не менее 44–48 pt по высоте; разделение опасных действий (удаление) от обычных.
7. **Краткая сводка по заданию** — в списке заданий показывать: объект, срок, статус (черновик/подписан/отправлен), иконку «есть неотправленные данные».
8. **Прогресс заполнения осмотра** — уже есть индикатор; дополнительно: «Заполнено 12 из 18» с перечислением недостающих пунктов (например, «нет фото таблички»).
9. **Поиск по заданиям и оборудованию** — поле поиска по названию, номеру, адресу с фильтром без перезагрузки всего списка.
10. **Сохранение последнего выбора ОПО/инженеров** — запоминать последние выбранные ОПО и инженеров по методам НК и подставлять при новом обследовании (локально).
11. **Тёмная/светлая тема** — переключатель в настройках с сохранением выбора и применением ко всему приложению.
12. **Увеличение фото в отчёте** — в форме при просмотре приложенных фото (табличка, схема, дефекты) возможность увеличить по нажатию (fullscreen).
13. **Камера с подсказкой** — при первом выборе «Сфотографировать табличку» краткая подсказка: «Снимите крупно заводскую табличку».
14. **Список «Недавние»** — раздел или вкладка «Недавно открытые» задания/оборудование для быстрого возврата.
15. **Фильтры в списке заданий** — по статусу (в работе / выполнено), по дате, по объекту; сохранение последнего фильтра.
16. **Уведомления о синхронизации** — после успешной синхронизации: «Отправлено 2 обследования»; при ошибке: «Не удалось отправить 1 обследование. Проверьте интернет и повторите».
17. **Доступность (accessibility)** — поддержка TalkBack/VoiceOver: осмысленные подписи к кнопкам и полям; достаточный контраст текста и фона.
18. **Сохранение черновика по таймеру** — уже есть автосохранение; показывать пользователю: «Черновик сохранён в …» (время последнего сохранения) внизу формы.
19. **Экран «О приложении» и помощь** — раздел с версией приложения, ссылкой на правила/инструкцию, контактами поддержки и кнопкой «Очистить локальный кэш» с подтверждением.

### Продолжение (очередная партия)

- **Бэкенд:** проверка целостности вложений перед генерацией отчёта — отсутствующие файлы из `document_files` логируются в консоль (inspection_id + список ключей).
- **Бэкенд:** генерация DOCX во временный файл с последующим `os.replace()` в финальный путь; при исключении временный файл удаляется (нет «битого» отчёта).
- **Мобильное, синхронизация:** уведомления после синхронизации — «Отправлено N обследований» / «Не удалось отправить M. Проверьте интернет и повторите» в зависимости от результата.
- **Мобильное, форма обследования:** по нажатию на приложенное фото (табличка, схема) открывается полноэкранный просмотр с зумом (InteractiveViewer) и кнопкой закрытия.
- **Мобильное, форма обследования:** под кнопками «Сохранить»/«Подписать» выводится время последнего автосохранения черновика: «Черновик сохранён: HH:mm».

### Очередная партия (автоулучшения)

- **Офлайн-вход:** при отсутствии кэша заданий/оборудования показывается развёрнутая подсказка: «Для работы офлайн сначала войдите при подключённом интернете и откройте список заданий».
- **Камера с подсказкой:** при первом нажатии «Сфотографировать табличку» или «Сфотографировать схему» показывается диалог с подсказкой (раз показ сохраняется в SharedPreferences).
- **Крупные зоны нажатия:** кнопки «Сохранить (черновик)» и «Подписать / Завершить» с минимальной высотой 48 pt и явной height: 52.
- **Бэкенд:** единый формат ошибок API — глобальный обработчик HTTPException возвращает тело `{ "detail", "code", "errors" }` (code: VALIDATION_ERROR, UNAUTHORIZED, NOT_FOUND и т.д.).
- **Список заданий:** иконка «облако отключено» (cloud_off) в карточке задания, если есть локальный черновик или подписанное, ожидающее синхронизации; semanticLabel для доступности.

### Очередная партия (водяной знак, синхронизация, фильтры, доступность)

- **Бэкенд:** водяной знак «ЧЕРНОВИК» в нижнем колонтитуле при генерации отчёта со статусом DRAFT (все три типа отчётов: диагностика, краткий, полный по сосуду).
- **Синхронизация:** при неудачной загрузке файла ключ сохраняется в `failed_document_keys`; при следующей синхронизации по этому опроснику загружаются только файлы из этого списка; при успехе ключ удаляется.
- **Мобильное, форма осмотра:** сохранение последнего выбранного ОПО и инженеров по методам НК в SharedPreferences; при открытии экрана подставляются последние выбранные значения (если нет данных из черновика/оборудования).
- **Мобильное, список заданий:** сохранение последнего фильтра (статус, сортировка, направление) в SharedPreferences и восстановление при открытии экрана.
- **Мобильное, доступность:** осмысленные подписи Semantics для кнопок «Синхронизировать» (экран синхронизации), «Сохранить (черновик)» и «Подписать / Завершить» (форма осмотра); в списке заданий кнопка синхронизации уже имела label.

### Очередная партия (pull-to-refresh, валидация API)

- **Мобильное, п.3:** Pull-to-refresh на экране списка оборудования (RefreshIndicator с ref.refresh(equipmentListProvider)); на экранах заданий и ОПО уже был.
- **Бэкенд, п.10:** Валидация при приёме данных: при создании обследования (POST /api/inspections) проверяются обязательное поле equipment_id (UUID), опциональные status (из списка DRAFT/SIGNED/APPROVED/COMPLETED), data (должен быть объектом), assignment_id (UUID); при ошибках возвращается 400 с массивом errors (field, message). При обновлении опроса ОПО (PUT /api/opos/{id}/survey) проверяется наличие и тип survey_data (объект); ошибки в том же формате.

### Очередная партия (тёмная/светлая тема)

- **Мобильное, п.11:** Переключатель темы в профиле: в разделе «Внешний вид» пункт «Тема» с выбором «Светлая», «Тёмная», «Как в системе». Выбор сохраняется в SharedPreferences и применяется ко всему приложению (MaterialApp theme/darkTheme/themeMode). Реализовано через Riverpod (themeModeProvider).

### Очередная партия (список «Недавние»)

- **Мобильное, п.15:** Раздел «Недавно открытые» на экране заданий: при открытии задания (переход в форму осмотра) запись добавляется в список недавних (до 10, по assignment_id). Вверху списка заданий отображается горизонтальная полоса чипов «Недавно открытые»; по нажатию открывается то же задание (оборудование берётся из офлайн-кэша или с сервера). Сервис RecentService, хранение в SharedPreferences.

### Очередная партия (аудит, OpenAPI)

- **Бэкенд, п.7:** Аудит изменений: в модели Inspection добавлены поля `created_by`, `updated_by` (FK на users); в Questionnaire — `created_by`, `updated_by`. Миграция при старте: ADD COLUMN IF NOT EXISTS. При создании обследования (POST /api/inspections) при наличии авторизации заполняется `created_by`; при смене статуса (PATCH status) — `updated_by`. Создаваемый опросник получает того же `created_by`.
- **Бэкенд, п.20:** Документация API: у FastAPI заданы title «ЕС ТД НГО — API», описание (авторизация Bearer, формат ошибок, разделы), теги для группировки в OpenAPI (auth, assignments, equipment, inspections, questionnaires, reports, opos). Схема доступна по /openapi.json и в Swagger UI.

### Очередная партия (бэкап, кэш, пакетная выгрузка)

- **Бэкенд, п.8:** Резервное копирование: скрипт `backend/scripts/backup.py` — дамп БД через `pg_dump`, копирование каталогов `uploads` и `reports` в `backups/backup_YYYYMMDD_HHMMSS`. Параметры из env: DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASS, UPLOADS_DIR, REPORTS_DIR. Аргументы: `--output-dir`, `--skip-db`, `--skip-files`. Скрипт `backend/scripts/restore.py` — восстановление из каталога бэкапа (выполнение database_dump.sql, копирование uploads и reports); аргумент `--dry-run`.
- **Бэкенд, п.11:** Кэширование справочников: in-memory кэш с TTL 300 сек для GET /api/opos (по workshop_id + enterprise_id), GET /api/equipment-types, GET /api/engineers. Инвалидация при создании/обновлении ОПО и при создании типа оборудования.
- **Бэкенд, п.12:** Пакетная выгрузка отчётов: POST /api/reports/bulk-export — тело `{"inspection_ids": ["uuid", ...], "report_type": "TECHNICAL_REPORT"}`; макс. 15 id. Для каждого обследования генерируется DOCX во временный каталог, все файлы упаковываются в ZIP и возвращаются как attachment (reports.zip). Доступ с учётом роли (инженер видит только свои обследования).
- **Бэкенд, п.19:** Роли и права на отчёты: при генерации отчёта (POST /api/reports/generate и POST /api/reports/bulk-export) для роли «engineer» проверяется принадлежность обследования (inspector_id, performed_by или created_by = текущий пользователь); при отсутствии прав возвращается 403 с сообщением «Нет прав на генерацию отчёта по этому обследованию». Роли admin/chief_operator/operator могут генерировать отчёты по любым обследованиям.

### Очередная партия (метрики, синхронизация по таймеру)

- **Бэкенд, п.9:** Метрики и мониторинг: счётчик запросов (http_requests_total) в middleware, время и количество генерации отчётов (report_generation_seconds_sum, report_generation_count). Эндпоинт GET /metrics возвращает метрики в формате Prometheus (text/plain).
- **Мобильное, п.16:** Синхронизация по таймеру: периодическая задача Workmanager «periodicSync» каждые 15 минут при наличии сети (Constraints(networkType: NetworkType.connected)); после синхронизации показывается уведомление при успешной отправке или при ошибках. Инициализация Workmanager и регистрация задачи при старте приложения (main.dart).
