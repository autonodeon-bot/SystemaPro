# Выжимка: контекст и продолжение развития системы

**Дата:** 09.02.2025  
**Система:** ЕС ТД НГО (SystemaPro) — платформа технического диагностирования НГО.

---

## 1. Текущее состояние

- **Веб:** React 18, TypeScript, Vite, Tailwind. Роли: admin, chief_operator, operator, engineer. API_BASE и версия в `constants.ts`.
- **Бэкенд:** FastAPI, PostgreSQL (SSL), роутеры вынесены (auth, access, hierarchy, assignments, report_templates, equipment_history). Остальное в `main.py` (~146 эндпоинтов). Есть `/health`, единый формат ошибок, аудит (created_by/updated_by), OpenAPI, метрики Prometheus, бэкап/restore, кэш справочников, пакетная выгрузка отчётов, водяной знак «ЧЕРНОВИК», проверка прав на отчёты по ролям.
- **Мобильное:** Flutter, офлайн-режим, черновики в SharedPreferences + `offline_documents`, синхронизация с повторной отправкой только failed-файлов. Workmanager — периодическая синхронизация каждые 15 мин. Тёмная/светлая тема, недавние задания, pull-to-refresh, сохранение фильтров и последних ОПО/инженеров, семантика для доступности.

- Кэш справочников (ОПО, equipment-types, engineers) с TTL 300 с.

- Роли и права на отчёты (engineer — только свои обследования).

- Мобильное: pull-to-refresh на оборудовании, тёмная/светлая тема, недавние задания, сохранение фильтров и ОПО/инженеров, подсказка при офлайн без кэша, подсказка при первом фото таблички/схемы, крупные кнопки, семантика.

## 3. Приоритеты развития (из DEVELOPMENT-PROPOSALS и IMPROVEMENTS-20x20)

### Быстрые победы (1–2 недели)
- **Проверка сети перед синхронизацией** — перед sync проверять connectivity (или `/health`), показывать «Нет интернета», не тратить попытки. ✅ Реализовано в этой сессии.
- QR-коды: генерация в вебе, сканер в мобильном, быстрый переход к оборудованию.
- Превью отчёта в вебе перед скачиванием (DOCX/PDF).

### Критичные (1–3 месяца)
- Система уведомлений: push, email, внутренние в вебе; напоминания о сроках и просрочках.
- История жизненного цикла оборудования: хронология, графики трендов (толщина, ресурс).
- GPS-штампы и автосохранение (частично есть; усилить EXIF и индикацию).

### Важные (3–6 месяцев)
- Планирование и календарь обслуживания; напоминания за 30/14/7 дней.
- Расширенная аналитика и BI-дашборды.
- Электронная подпись отчётов и актов.
- Управление рисками и соответствие нормам.

### Из списка 20+20 (ещё не закрыто)
- Очередь загрузки файлов с 2–3 повторами и логированием.
- Единый формат дат и чисел в отчётах.
- Версионирование отчётов (шаблон при создании).
- Лимиты размера/типа файлов на бэкенде.
- Сжатие изображений перед отправкой (мобильное).
- Планировщик напоминаний.
- Шаблоны отчётов из конфигурации (JSON/БД).
- Единый справочник дефектов.
- Пакетная генерация отчётов (частично есть bulk-export).
- Мониторинг и алерты сервера.

## 4. Рекомендуемые следующие шаги

1. **QR-коды** — генерация в веб (страница оборудования/карточка), сканер в мобильном, переход к оборудованию по коду.
2. **Проверка сети перед синхронизацией** — выполнена: перед `syncPendingInspections()` и перед синхронизацией заданий проверяется доступность API (`checkConnection()`); при отсутствии сети показывается «Нет интернета» без попытки синхронизации.
3. **Превью отчёта** — в ReportGeneration/ReportViewer возможность открыть сгенерированный отчёт в новой вкладке (blob URL) перед скачиванием.
4. Продолжать вынос эндпоинтов из `main.py` (inspections, reports, users) в отдельные роутеры по мере изменений.
