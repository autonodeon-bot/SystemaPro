# Скрипты для управления Backend

## Описание скриптов

### 1. `update-backend-files.bat` ⚡ (РЕКОМЕНДУЕТСЯ при лимите Docker Hub)
**Назначение:** Обновление файлов backend без пересборки образа Docker

**Когда использовать:**
- Docker Hub достиг лимита запросов (429 Too Many Requests)
- Нужно быстро обновить код без полной пересборки
- Изменились только Python файлы (не зависимости)

**Что делает:**
1. Копирует все Python файлы на сервер
2. Копирует файлы напрямую в работающий контейнер
3. Перезапускает контейнер
4. Проверяет работоспособность API

**Время выполнения:** ~30 секунд

---

### 2. `rebuild-backend.bat` 🔨
**Назначение:** Полная пересборка backend с нуля

**Когда использовать:**
- Изменились зависимости (requirements.txt)
- Изменился Dockerfile
- Нужна чистая пересборка
- Docker Hub доступен

**Что делает:**
1. Копирует все файлы на сервер
2. Останавливает и удаляет старый контейнер
3. Удаляет старый образ
4. Пересобирает образ БЕЗ КЭША
5. Запускает новый контейнер
6. Проверяет работоспособность

**Время выполнения:** 2-5 минут

**Особенности:**
- Автоматически проверяет доступность Docker Hub
- При лимите Docker Hub использует кэш или предлагает альтернативу

---

### 3. `check-auth-fix.bat` ✅
**Назначение:** Проверка работоспособности авторизации

**Когда использовать:**
- После обновления backend
- При проблемах с авторизацией
- Для проверки корректности работы API

**Что делает:**
1. Проверяет подключение к серверу
2. Проверяет существование контейнера
3. Запускает контейнер, если остановлен
4. Проверяет структуру файлов
5. Инициализирует пользователей в БД
6. Тестирует endpoint `/api/auth/login`
7. Показывает логи

**Время выполнения:** ~20 секунд

---

### 4. `diagnose-backend.bat` 🔍
**Назначение:** Полная диагностика backend

**Когда использовать:**
- При непонятных проблемах
- Для глубокой диагностики
- Перед обращением за помощью

**Что делает:**
1. Проверяет подключение к серверу
2. Проверяет версии Docker и docker-compose
3. Показывает все контейнеры backend
4. Проверяет статус контейнера
5. Проверяет структуру файлов
6. Показывает зарегистрированные маршруты FastAPI
7. Проверяет подключение к БД
8. Показывает логи
9. Проверяет сеть и порты
10. Показывает статус docker-compose

**Время выполнения:** ~1 минута

---

### 5. `quick-fix-backend.bat` 🚀
**Назначение:** Быстрое исправление проблем

**Когда использовать:**
- Нужно быстро исправить проблему
- Комбинирует обновление и проверку

**Что делает:**
1. Проверяет контейнер
2. Запускает `update-backend-files.bat`
3. Запускает `check-auth-fix.bat`
4. Показывает итоговый статус

**Время выполнения:** ~1 минута

---

## Рекомендуемый порядок действий

### При проблеме с авторизацией:
1. Запустите `diagnose-backend.bat` для диагностики
2. Если контейнер не запущен или файлы устарели:
   - При лимите Docker Hub: `update-backend-files.bat`
   - Если Docker Hub доступен: `rebuild-backend.bat`
3. Запустите `check-auth-fix.bat` для проверки

### При обновлении кода:
1. Если изменились только Python файлы:
   - `update-backend-files.bat` (быстро, без пересборки)
2. Если изменились зависимости или Dockerfile:
   - `rebuild-backend.bat` (полная пересборка)

### При лимите Docker Hub (429 Too Many Requests):
- **Используйте `update-backend-files.bat`** - он не требует скачивания образов
- Или подождите 1-2 часа и используйте `rebuild-backend.bat`

## Устранение проблем

### Контейнер не найден
```batch
# Запустите rebuild-backend.bat для создания контейнера
```

### Endpoint возвращает 404
```batch
# 1. Проверьте структуру файлов
diagnose-backend.bat

# 2. Обновите файлы
update-backend-files.bat

# 3. Проверьте логи
docker logs es_td_ngo_backend
```

### Docker Hub лимит (429)
```batch
# Используйте update-backend-files.bat вместо rebuild-backend.bat
# Он не требует скачивания образов
```

### Контейнер не запускается
```batch
# 1. Проверьте логи
docker logs es_td_ngo_backend

# 2. Проверьте конфигурацию
diagnose-backend.bat

# 3. Пересоберите
rebuild-backend.bat
```
