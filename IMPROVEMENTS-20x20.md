# Улучшения системы и мобильного приложения

## Офлайн и онлайн: что должно работать

### Для корректной работы офлайн
- **Сохранение черновика** — все данные формы, фото таблички, схема контроля, документы 1–17, дефекты ВИК сохраняются локально (SharedPreferences + папка `offline_documents`).
- **Автосохранение** — черновик сохраняется по таймеру и при выходе с экрана диагностики.
- **Восстановление при повторном входе** — при открытии оборудования подгружается локальный черновик (если есть) или данные последней инспекции с сервера.
- **Файлы** — все выбранные/снятые фото и файлы копируются в `offline_documents`, чтобы пути оставались валидными после перезапуска приложения.

### Для корректной работы онлайн (после синхронизации)
- **Синхронизация** отправляет данные инспекции на сервер, затем загружает каждый файл из `document_files` (в т.ч. factory_plate_photo, control_scheme_image, документы 1–17, vd_*).
- **Проверка сети** перед запуском синхронизации (рекомендуется добавить) — показывать предупреждение, если нет интернета.
- **Повторная синхронизация** — при частичной ошибке (не все файлы загружены) элементы остаются в очереди; можно нажать «Синхронизировать» снова.

### Что обязательно заполнять для полного отчёта
- Дата обследования, исполнители, организация.
- Карта обследования: наименование, заводской/регистрационный номер, производитель, год, диаметр/давление/толщина (для сосуда).
- Фото заводской таблички.
- Схема контроля (фото или стандартный чертёж) и при необходимости точки замера УЗТ.
- Сканы документов по перечню 1–17 (где прикладываются).
- Дефекты ВИК с фото (если есть).
- Заключение.
- Оборудование для поверок (выбор).

## 20 улучшений для всей системы

1. **Проверка доступности сети перед синхронизацией** — в мобильном приложении перед вызовом sync проверять connectivity и показывать «Нет интернета», не тратя попытки.

2. **Очередь загрузки файлов с повторными попытками** — при ошибке загрузки одного файла делать 2–3 повтора с задержкой и только потом помечать элемент как failed; логировать, какой именно файл не загрузился.

3. **Веб: превью отчёта перед скачиванием** — возможность посмотреть сгенерированный отчёт (или первые страницы) в браузере перед сохранением DOCX/PDF.

4. **Единый формат дат и чисел** — во всех отчётах и API использовать единый формат (например, дата «ДД.ММ.ГГГГ», числа с запятой/точкой по ГОСТ).

5. **Версионирование отчётов** — сохранять в БД версию шаблона/генератора при создании отчёта и возможность «пересобрать» отчёт по новой версии шаблона.

6. **Резервное копирование и экспорт данных** — периодический экспорт ключевых данных (оборудование, инспекции) в JSON/архив для администратора.

7. **Аудит изменений** — логирование кто и когда изменил назначение, статус задания, заключение инспекции (для веб и критичных полей).

8. **Ограничение размера и типа файлов** — на бэкенде явные лимиты (например, 10 МБ на файл, только image/* и PDF) с понятным сообщением об ошибке.

9. **Сжатие изображений перед отправкой** — в мобильном приложении опционально сжимать фото до заданного разрешения/качества перед сохранением в offline_documents и отправкой, чтобы ускорить синхронизацию и уменьшить место.

10. **Планировщик напоминаний** — напоминания о сроках следующей диагностики, истечении сертификатов, просроченных заданиях (на сервере или через push).

11. **Шаблоны отчётов из конфигурации** — хранить структуру разделов отчёта (заголовки, порядок приложений) в JSON/БД, чтобы менять без правки кода.

12. **Водяной знак или штамп «Черновик»** — при генерации отчёта из черновика или без подписи добавлять на каждую страницу пометку «ЧЕРНОВИК» или «КОПИЯ».

13. **Подпись/ЭЦП** — интеграция с простой подписью (например, изображение подписи + дата) или ЭЦП для финального отчёта и актов.

14. **Роли и права** — разграничение: только просмотр, редактирование своих заданий, утверждение отчётов, доступ к финансовым/админ-функциям.

15. **Интеграция с 1С/учётом** — выгрузка актов и отчётов в форматах, пригодных для передачи в бухгалтерию/1С (номенклатура, суммы, реквизиты).

16. **Дашборд и аналитика** — сводки по объектам: сколько диагностик за период, просрочки, типы дефектов, загрузка инженеров.

17. **Нормативная база в системе** — справочник документов (ФЗ, РД, ГОСТ), привязка к видам оборудования и срокам проверок для автоматических напоминаний и подсказок в отчёте.

18. **Единый справочник дефектов** — коды и формулировки дефектов с возможностью выбора из списка в мобильном приложении и однозначным отображением в отчёте.

19. **Пакетная генерация отчётов** — возможность сформировать отчёты по нескольким инспекциям/оборудованиям одной кнопкой (ZIP с DOCX).

20. **Мониторинг и алерты сервера** — мониторинг места на диске (uploads, reports), времени ответа API, падения воркеров; уведомление администратору при критичных сбоях.

## 20 улучшений юзабилити мобильного приложения

1. **Индикатор офлайн/онлайн** — в шапке или на экране синхронизации показывать иконку и текст «Офлайн» / «Онлайн», чтобы пользователь понимал, сохраняются ли данные только локально.

2. **Подсказки при первом запуске** — короткий онбординг: «Черновики сохраняются локально», «Синхронизируйте при наличии интернета», «Фото лучше делать в приложении».

3. **Прогресс заполнения в виде процента/полоски** — на экране диагностики показывать «Заполнено 70%» и список недостающих обязательных полей (уже есть частично — усилить визуально и в одном месте).

4. **Быстрый скролл к блоку** — оглавление/якоря по разделам (Карта обследования, УЗТ, Дефекты, Заключение) для перехода к нужному разделу без прокрутки.

5. **Сохранение при сворачивании приложения** — при переходе в фон сразу сохранять черновик (или убедиться, что автосохранение и didChangeAppLifecycleState это делают).

6. **Крупные зоны нажатия** — кнопки «Сфотографировать», «Выбрать из галереи», «Стандартный чертёж» и чекбоксы документов с достаточным padding для удобного нажатия на улице/в перчатках.

7. **Подтверждение при выходе с несохранёнными изменениями** — диалог «Есть несохранённые данные. Сохранить черновик?» при нажатии «Назад», если форма изменена.

8. **Превью фото в списке дефектов ВИК** — миниатюры прикреплённых фото в карточке дефекта, возможность удалить одно фото из нескольких.

9. **Фильтры и поиск в списке оборудования** — по названию, инвентарному номеру, статусу задания, объекту.

10. **Сортировка заданий** — по дате, по приоритету, по объекту; запоминание выбранной сортировки.

11. **Цветовая маркировка статусов** — черновик (оранжевый), подписан/ожидает синхронизации (жёлтый), синхронизирован (зелёный), просрочен (красный).

12. **Группировка по объекту/заданию** — в списке оборудования группировать по заданию или объекту с возможностью свернуть/развернуть.

13. **Кэширование списка заданий и оборудования** — при отсутствии сети показывать последний загруженный список с пометкой «Данные на дату …» и кнопкой «Обновить».

14. **Доступ к камере и галерее без лишних шагов** — минимум диалогов; при выборе «Камера» сразу открывать камеру, при «Галерея» — выбор файла/фото.

15. **Редактирование даты и времени в удобном формате** — единый date/time picker с форматом ДД.ММ.ГГГГ и при необходимости временем.

16. **Автозаполнение организации и исполнителей** — запоминать последние введённые значения и предлагать их в следующих диагностиках (или подставлять из профиля).

17. **Копирование данных из предыдущей инспекции** — кнопка «Взять из последней диагностики» для карты обследования и части полей, чтобы не вводить повторно.

18. **Тёмная тема по умолчанию** — уже используется; опция «Светлая тема» в настройках для работы в помещении.

19. **Доступность (accessibility)** — подписи к полям, достаточный контраст, возможность увеличить шрифт в настройках; озвучивание ключевых кнопок для screen readers.

20. **Краткая справка в приложении** — раздел «Помощь» или «?» с ответами: как сохранить черновик, как синхронизировать, что делать при ошибке «не все файлы отправлены», куда звонить при проблемах.

## DOCX: что уже сделано

- В генераторе Word (`word_generator.py`) включена настройка стилей в `_setup_styles`:
  - поля страницы: левое 1.5", остальные 1.25";
  - шрифт по умолчанию: Times New Roman 12 pt;
  - межстрочный интервал 1.15, отступ после абзаца 6 pt;
  - заголовки Heading 1–3: жирный Times New Roman 14/12/11 pt с отступами до и после.

Дополнительные плагины для Python не обязательны: `python-docx` и `Pillow` уже используются. Для ещё более сложного оформления (например, точное позиционирование картинок или сложные колонтитулы) можно рассмотреть шаблоны на базе `python-docx-template` (Jinja2) в будущем.
